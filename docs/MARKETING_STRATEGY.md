# YUMEMI マーケティング戦略

策定日：2026-10-30  
対象サイト：https://yumemi-official.com/  
位置づけ：読者・集客・コンテンツ投資・評価の判断基準。実装手順や記事の執筆要領は扱わない。編集上の品質基準は [EDITORIAL.md](./EDITORIAL.md) を参照する。

## 1. 目的と提供価値

YUMEMIを「夢を見て、その内容が気になる人」が訪れるメディアへ育てる。特に、悪夢で苦しむ人が、安心につながる情報や必要な支援へたどり着けることを大切にする。

提供価値は「気になる夢を調べて、安心して今日を過ごせる」。検索流入とPVを増やす一方、恐怖をあおって回遊させる運営はしない。

夢の内容を調べる需要を入口に、悪夢への対処、眠りの振り返り、相談先へつなぐ。将来のアプリや収益化への導線は、この価値を損なわない範囲で検討する。現段階では記事の有用性と検索流入の基盤づくりを優先する。

## 2. 読者

集客対象は、夢の意味や理由が気になる日本語の読者全般とする。ブランドの中心読者は、悪夢や睡眠に悩む大人の女性。女性向けの語り口やテーマを持ちながら、一般的な夢の記事で他の読者を排除しない。

| 読者の状態 | 知りたいこと | 届ける価値 |
|---|---|---|
| 印象的な夢を見た | どんな意味？ほかの人も見る？ | 内容を探せる辞典、解釈の限界、気持ちを振り返る視点 |
| 怖い夢で不安になった | 現実に起こる？どう落ち着く？ | 不安を強めない説明と、今できる対処 |
| 悪夢が続いて困っている | なぜ続く？眠るのが怖い | 頻度・生活への影響に応じた情報、相談先 |
| 眠りや体調を見直したい | 何を記録・改善すればよい？ | 睡眠習慣、夢日記、女性の眠りに関する情報 |

## 3. ポジショニングと守る方針

夢占いの検索需要に応えながら、悪夢で困る読者への支援を強みにする。占いだけで結論づけず、読者が必要に応じて睡眠・健康の情報へ進める構成を持つ。

- 夢占いの文化的・娯楽的解釈と、科学的・医学的説明を明確に分ける。
- 夢の内容だけで病気、心理状態、妊娠、災害、他人の行動を断定しない。
- 「必ず不幸になる」「予兆を知らないと危険」など、不安を集客に利用しない。
- 状況別の項目数や文字数を増やすこと自体を差別化にしない。
- 読者が答えを得て離脱することも成功と捉える。PVや滞在時間だけで価値を判断しない。
- 将来の天気・服装分野への拡張は、夢と睡眠の基盤を育ててから別途判断する。

## 4. 検索需要の読み方

初期判断の材料は、ユーザー提供の2026-10-30のキーワードプランナー画像。地域・対象期間などの詳細条件は未確認であり、示されたレンジを概算として扱う。

「競合性：低」は広告主間の競合を示し、自然検索で上位を取る難易度ではない。月間平均検索数には類似語が含まれ得るため、各行を足して市場規模やPV予測にしない。検索数の大きさだけで優先順位を決めず、読者との適合性、既存記事との関係、検索結果の意図、制作・検証の負担を合わせて判断する。

## 6. 読者導線

夢占い辞典から具体的な夢を探せるようにする。個別記事からは、関連する夢と、その読者に必要な支援へつなぐ。すべての読者に一律の回遊を求めない。

| 記事を読んだときの状態 | 次に案内する情報 |
|---|---|
| 別の夢も調べたい | 関連する夢、辞典の入口 |
| 目が覚めても怖い | 悪夢を見た直後の対処 |
| 同じ夢が続く | 反復する悪夢、記録の考え方 |
| 眠るのが怖い | 眠りたくない夜の過ごし方 |
| 眠りや日中の生活に支障がある | 医療機関などへの相談目安 |
| 自分の傾向を知りたい | 夢日記、睡眠の振り返り |

夢占いを信じることを、対処法や相談先を読む前提にしない。読み終わった人が必要な情報を得られることを優先する。

## 7. 制作の優先順位

2026-10-30の制作方針：最初の集客エースクエリを「追いかけられる夢」とし、対応記事を `/articles/chased-dream/` に集約する。需要レンジと悪夢支援への接続性を基に選定した仮説であり、最多PVを保証するものではない。辞典の入口は `/articles/dream-meaning-guide/`、悪夢支援の柱は既存の `/articles/nightmare-guide/` とする。夢の内容に関する記事からは辞典と関連する夢へ、困りごとがある読者には悪夢支援の柱・直後の対処・反復・相談先へリンクする。既存の関連する記事からもエース記事へリンクを返す。

最初の追加バッチは新規8記事（No.13、14、15、16、17、18、7、8）と既存No.1・2の強化。全体16記事の段階で、夢の辞典への入口と悪夢への支援を揃える。

以後は全体24→32→40記事を目安に追加する。後続バッチの具体的な順番は固定せず、Search Consoleの表示クエリと既存記事の不足から決める。記事数を満たすための薄い記事は追加しない。

各バッチは「対象クエリ・読者の疑問・構成・根拠資料・内部リンク」を提示し、ユーザー承認後に制作・検証・公開する。方針が未承認の新規分野へ自動で拡張しない。

## 8. 計測と改善

計測基盤の設定日を2026-10-30とする。GA4は閲覧行動、Search ConsoleはGoogle検索での発見・流入を評価する。検索クリック数とPVは別の指標として扱う。

| 評価対象 | 主な指標 | 判断すること |
|---|---|---|
| サイト全体の成長 | GA4の表示回数（PV）、アクティブユーザー、自然検索経由の流入 | 読者に届く規模が伸びているか |
| 検索での発見 | Search Consoleの表示回数、クリック数、クエリ、平均掲載順位 | どの疑問に対して記事が見つかっているか |
| 検索結果での選ばれ方 | クエリ・ページ別CTR | タイトルと説明が検索意図に合うか |
| 記事の貢献 | 記事別PV、ランディングページ、エンゲージメント | 入口として働く記事と改善対象はどれか |
| 支援への接続 | 関連記事や相談先への導線 | 必要な次の情報へ進めるか |

支援リンクの利用は、専用の計測が必要な場合がある。現時点で全導線を計測済みとは扱わない。低PVや短い滞在時間だけで、相談・対処記事を削除しない。

週次で直近7日と前7日、月次で直近28日と前28日を比較する。公開直後はデータが少なく変動が大きいため、短期の順位だけで方針を変えない。初月は基準値を集め、数値目標は実測後にユーザーと決める。検索ボリュームから獲得PVや上位掲載を保証しない。

改善の順番は以下を基本とする。

1. インデックス・配信など、読者がアクセスできない問題を解消する。
2. 表示されているのにクリックされない記事は、順位・クエリを見てタイトルや説明を見直す。
3. 想定外のクエリでも、読者の疑問が記事の範囲内なら内容を補う。
4. 同じ意図で複数記事が競合する場合は、役割の整理・統合を検討する。
5. 既存記事で答えられない、目的に合う疑問が見つかったときに新規企画へ進む。

## 9. 方針変更の判断基準

新規企画や変更は、以下の問いに答えてから採用する。

- 夢を見て気になる人、または悪夢で困る人の役に立つか。
- 既存記事への追記では足りず、独立した検索意図があるか。
- 占いと事実を分け、信頼できる内容を制作・維持できるか。
- 不安をあおらず、適切な次の行動へ案内できるか。
- 検索需要や実際の流入データに、優先する理由があるか。

中心読者・提供価値・対象領域・収益化方針を変えるときは、変更理由とデータをユーザーに提示して承認を受け、本書を更新する。検索数の大きい無関係な語や、一時的な順位変動だけを理由に戦略を変えない。
